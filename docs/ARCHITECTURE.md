# PTS Architecture (Living Doc)

## Product shape (current)
- **Not** a marketplace/matching product in v1.
- Start as a **program delivery + therapist operations** system for a structured 6-week track.

## Users
- **Client**: chronic musculoskeletal pain; wants sustained periodic therapist support.
- **Provider**: India-based therapists; need a consistent protocol + workflow.

## Core capabilities (phased)
### Phase 0 (docs-first)
- Crisp wedge + program definition
- Safety/privacy posture

### Phase 1 (MVP software)
- Client intake + eligibility/red flags + consent
- Program track delivery (weekly cadence + daily micro-practices)
- Weekly check-in + reflections
- Optional flare-up protocol (with strict boundaries)
- Minimal provider console (view client summary + track template)

### Deferred
- Matching/marketplace
- Payments
- Rich scheduling

## Proposed system (TBD stack)
- Web app (client + provider console)
- API service (auth, program data)
- Storage (only with consent)
